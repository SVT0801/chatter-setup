# Chatter AI — первая установка

Скрипт ставит Chatter AI на **ваш отдельный** сервер. Запускать под пользователем с `sudo`.
Нужно 4 шага: скачать скрипт, `prepare`, `install`, `check`.

SVT сообщает вам три вещи:

- домен портала;
- номер версии (`vX.Y.Z`);
- два токена доступа. Они приходят **отдельно** от этой инструкции.

## Требования

| Что | Требование |
|-----|-----------|
| ОС | Debian 12/13 или Ubuntu 24.04/26.04 |
| Ресурсы | минимум 2 CPU, 4 ГБ RAM, 30 ГБ свободно |
| Рекомендуем | 4 CPU, 8 ГБ RAM |
| Сервер | отдельный, без других сайтов |
| Порты | 80 и 443 свободны и открыты снаружи, включая firewall провайдера |
| Исходящий HTTPS | GitHub, ghcr.io, Docker Hub, PyPI, Let's Encrypt, репозитории ОС |
| Домен | A-запись на IP сервера |
| Токены | `CHATTER_TOKEN` и `GHCR_TOKEN` от SVT |
| Версия | номер `vX.Y.Z` присылает SVT |

## Домен

- Создайте A-запись домена на IP сервера.
- Создайте AAAA-запись только если у сервера есть глобальный IPv6.
- Cloudflare-прокси допустим.
- Режим SSL/TLS в Cloudflare: **Full** или **Full (strict)**. Не Flexible.
- Скрипт сам проверит, что проверка Let's Encrypt доходит до сервера.

## Токены

| Токен | Тип | Права |
|-------|-----|-------|
| `CHATTER_TOKEN` | fine-grained (`github_pat_…`) | только чтение, релизы |
| `GHCR_TOKEN` | classic (`ghp_…`) | только `read:packages`, образ интерфейса |

- Команда `install` спросит токены при установке.
- Ввод скрыт.
- Не пересылайте токены в мессенджерах.
- Не вставляйте токены в команды.
- Не храните токены в истории shell.

## Установка

Вставляйте команды **по одной стадии**: скачать → `prepare` → `install` → `check`. После каждой стадии смотрите последнюю строку `ИТОГ`: в ней число `FAIL` и `WARN`.

- `FAIL 0` — стадия прошла, переходите к следующей.
- Есть `FAIL` — у каждой строки есть подсказка «→ что сделать». Исправьте и повторите **ту же** команду (она продолжит с места обрыва; данные и `env/.env` сохраняются).

Пароль `sudo` сервера спросит система. Токены спросит `install`. Ввод скрыт. Ни пароль, ни токены в команды вставлять не нужно.

Запускайте внутри `tmux`. Если на сервере есть systemd, `install` идёт службой и обрыв SSH её не прерывает. Без systemd установка идёт в этой сессии: обрыв SSH её прервёт, поэтому нужен `tmux`.

```bash
sudo apt install tmux
tmux new -s chatter
```

### 1. Скачать скрипт

```bash
curl -fsSL https://raw.githubusercontent.com/SVT0801/chatter-setup/main/chatter-setup.sh -o chatter-setup.sh
```

### 2. Подготовить сервер

```bash
sudo bash chatter-setup.sh prepare --domain chatter.example.com
```

`prepare` проверяет и готовит сервер:

- обновления системы
- Docker
- firewall
- fail2ban
- автообновления безопасности
- время UTC
- пользователь `chatter`

Повторный запуск безопасен.

### 3. Установить

```bash
sudo bash chatter-setup.sh install --domain chatter.example.com --version vX.Y.Z
```

- Вместо `chatter.example.com` — ваш домен. Вместо `vX.Y.Z` — номер версии от SVT.
- `install` проверяет токены, DNS, порты и путь Let's Encrypt **до** изменений.
- Затем он ставит Chatter AI.
- Установка занимает 5–15 минут.
- В конце печатается баннер с адресом портала, строкой `Вход` и строкой `Studio`. Сохраните его.
- После установки публичная регистрация закрыта (`DISABLE_SIGNUP=true`). Новых сотрудников добавляет администратор в портале.

### 4. Проверить

```bash
sudo bash chatter-setup.sh check
```

- `check` только читает.
- Запускайте его в любой момент.
- После `install` и после `check` строка `ИТОГ` должна быть `FAIL 0`.

## После установки

- Откройте `https://chatter.example.com`.
- Логин и пароль первого входа — в строке `Вход` в конце установки в терминале.
- Портал попросит сменить пароль. Смените его сразу.
- Заполните профиль.

### Studio

- Studio (`https://chatter.example.com/project/default`) — служебная консоль базы данных.
- В ежедневной работе она не нужна.
- Пароль Studio печатается **один раз**, в баннере в конце установки (строка `Studio`). Повторно он не выводится.
- Сохраните его в менеджер паролей. Не пересылайте его в чат и почту.

## Обновления

- Портал → `/settings/updates` → кнопка «Оновити».
- SSH не нужен.

## Если что-то пошло не так

| Симптом | Что делать |
|---------|-----------|
| Порт 80 недоступен снаружи | Откройте 80 и 443 у провайдера (firewall, security group). Повторите `install` |
| Cloudflare в режиме Flexible | Cloudflare → SSL/TLS → режим **Full** или **Full (strict)**. Повторите `install` |
| Токен не принят | Проверьте токен и версию у SVT. Запросите новый токен. Повторите `install` |
| Мало места на диске | Освободите место до 30 ГБ. Повторите `install` |
| Обрыв SSH во время установки | Подключитесь снова. Откройте `tmux attach -t chatter`. Или повторите `install` |
| Лимит Let's Encrypt | Подождите час. Повторите `install` |
| Порт 80 или 443 занят | Нужен отдельный сервер без другого веб-сервера |
| Хочется «почистить» firewall | Не удаляйте правило ufw «docker-сеть → порт 8090». `prepare` создаёт его, оно нужно порталу. Порт 8090 в интернет не открывайте |

Не помогло? Соберите отчёт:

```bash
sudo bash chatter-setup.sh report
```

- Скопируйте блок между `----- CHATTER SUPPORT BEGIN -----` и `----- CHATTER SUPPORT END -----` целиком.
- Секреты в блоке замаскированы.
- Копия блока: `/var/log/chatter-support-<время>.txt` (права 600, только root).
- Отправьте блок в поддержку SVT.

## Доступ SVT

- SVT не заходит на ваш сервер без вашего запроса.
- SSH-доступ даёте вы сами, только для аварийной помощи.

Журнал подготовки: `/var/log/chatter-setup.log`.
Журнал установки: `/var/log/chatter-install.log`.
Если связь оборвалась, а установка идёт службой: `sudo tail -f /var/log/chatter-install.log`.
